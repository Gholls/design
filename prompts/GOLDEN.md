# 黄金样板间提示词（GOLDEN PROMPT）

> 本文件是整个项目的**唯一需求事实源**。所有约束写在这里，而不是代码里。
> 任何 code agent 拿到「本文 + 任一 designs/&lt;slug&gt;/DESIGN.md」，都应产出
> 一个同需求、不同人格的静态站点。需求一字不改，规范随意替换。

---

你是一名资深前端工程师兼品牌设计师。请严格依据下方需求与随附的 DESIGN.md 规范，
生成一个展示该设计规范全部性格的站点样板间。

## 一、产物契约（硬性）

1. 输出为**单个自包含的 `index.html`**（内联 CSS 与 JS；不引用任何网络字体、
   CDN、构建工具；允许 data URI；字体用规范声明的回退栈）。
   产物落点：`public/generated/<slug>/index.html`。
2. 双击即可在 `file://` 下完整运行；无后端、无外部请求。
3. 中文界面 + 品牌语境的可信样例数据。
4. 页面底部生成信息条：`由 AI agent 依 GOLDEN PROMPT + DESIGN.md「<规范名>」生成`。

## 二、规范消费（差异的来源，优先级高于你的默认审美）

- **Token 全部照搬**：把 DESIGN.md 的 YAML Token 逐值转成 CSS 自定义属性，
  页面样式只引用这些变量，禁止硬编码颜色/圆角/阴影/字体值。
- **components 指引**：规范中 `components.*`（button-primary 的圆角/底色/文字色、
  chips、inputs 等）决定对应组件的真实样式。
- **散文即指令**：规范 Overview/Elevation/Shapes/Do's and Don'ts 里每一句
  设计判断（例如「UI 退后，让产品说话」「阴影只出现在商品图上」「描边即层级」）
  都必须在页面上可见地执行。
- **指标决定气质**：Density/Variance/Motion 指标（无指标则依散文文气）控制
  留白节奏、版式不对称度与动效强度；Motion 为 0 时禁用全部 transition/animation。

## 三、产品内核（所有样板间固定为同一内容：GhollStudio）

每个样板间都是虚构软件工作室 **GhollStudio** 的官网 + 管理后台。
文案、功能、字段、数据示例必须按本节实现——内容恒定，风格随 DESIGN.md 变化。
顶栏必须提供醒目的「前台 / 后台」分段切换；管理视图命名统一「后台 · Studio 控制台」。

### 前台 · GhollStudio 官网
1. **导航**：字标 GhollStudio + 菜单（服务 / 案例 / 定价 / 登录）+ 主 CTA「进入后台」。
2. **Hero**：主张「把你的产品，交给我们收尾」+ 一句话副文 + 主/次动作 + 品牌化首屏视觉
   （由规范 Elevation/Shapes 决定形态：产品窗格 / 案例磁贴 / 终端 / 时间线，禁止外链图）。
3. **数据带**：已交付 128 个项目 · 在售服务 6 项 · 客户均分 4.9 · 覆盖 12 城。
4. **服务卡 ×4**：设计系统与 Token 工程 / Web·小程序交付 / AI 集成流水线 / 长期运维与审计。
5. **案例卡 ×3**：ProVision 商城（电商）、Atlas 财务台（金融后台）、Slot 预约云（SaaS）。
   每卡：CSS 抽象封面 + 一句成果指标 + 标签。
6. **流程四步**：需求体检 → 方案与报价 → 双周迭代交付 → 验收与运维。
7. **客户评价 ×2**（署名：客户公司 + 职位）；**定价三档**：起步 / 标准（推荐）/ 驻场。
8. **FAQ ≥4 条**；页脚四列 + 订阅输入框；底部生成信息条。

### 后台 · Studio 控制台（重点，必须完整可交互）
1. **KPI 4 卡**：本月交付(数值+环比)、进行中项目、待审核队列、月营收；至少两张带迷你趋势。
2. **项目卡片墙 ≥6 卡**：项目名、类型、负责人、进度条(%)、状态徽章；含一张「空项目」卡演示空态样式或列表提供清空按钮。
3. **工单表格 ≥8 行**：列 = 单号 / 项目 / 客户 / 阶段 / **审核状态下拉（select：待审核→复核通过/驳回重做/已上架，行内即时生效）** / 金额（右对齐 tabular）/ 更新时间；支持按金额排序与关键字筛选。
4. **审核动态**：每次下拉审核操作即时追加一条审核记录（操作+项目名+新状态），展示在「复核记录」面板——体现状态驱动。
5. **新建项目弹窗**：导航/卡片墙均有「新建项目」入口；模态含完整表单——项目名*（必填校验）、类型 select、负责人 select、开始日期 date、工期 range、标签输入、简介 textarea（maxlength+计数）、拖拽上传区、保存/取消；提交后新卡片进入卡片墙并更新「进行中」KPI。
6. **统计区**：月度交付柱状（可切 6/12 月）、服务类型环图（conic-gradient）、线索→签约漏斗。
7. **通知中心**：列表 + 「新增」「清空」；清空后显示空状态卡。
8. **组件带**：主/次/强调/危险/幽灵按钮（含禁用态）、四语义徽章、开关、骨架屏、Tooltip、面包屑。

### 前台 · 登录/注册视图
双 Tab（登录 / 注册）认证卡：邮箱+密码+记住我 / 注册含工作室名与协议勾选；焦点与校验态遵循规范。

### 交互要求（硬指标）
- 前台/后台切换、表格筛选排序、审核下拉、模态开合与表单校验、通知增删必须真实可用（原生 JS）。
- 所有视觉值来自规范 Token；时间线/色板等规范私有语汇要用在其位。

## 四、通用要求

- 键盘可达（Tab 顺序、焦点可见遵循规范 focus token）；对比度符合规范原则
- 响应式：≥1024px 完整；窄屏优雅折叠
- 完成后自查：代码顶部写「决策溯源注释」——每个关键界面决策来自规范的哪一行
