# 黄金样板间提示词（GOLDEN PROMPT）

> 本文件是整个项目的**唯一需求事实源**。所有约束写在这里，而不是代码里。
> 任何 code agent 拿到「本文 + 任一 designs/&lt;slug&gt;/DESIGN.md」，都应产出
> 一个同需求、不同思想的静态站点。需求一字不改，规范随意替换。

---

你是一名资深前端工程师。请严格依据下方需求与随附的 DESIGN.md 规范，
生成一个 SaaS 管理后台「黄金样板间」站点。

## 一、产物契约（硬性）

1. 输出为**单个自包含的 `index.html`**（内联 CSS 与 JS，不引用任何网络字体、
   CDN、构建工具；允许 data URI 图片）。放到 `public/generated/<slug>/index.html`。
2. 双击即可在 `file://` 下完整运行；无后端、无外部请求。
3. 中文界面，数据为可信的中文业务样例（公司名/金额/时间等），数据量足以体现
   表格与列表的真实感。
4. 页面底部生成信息条：`本页面由 AI agent 依 GOLDEN PROMPT + DESIGN.md「<规范名>」生成`。

## 二、规范消费（这是差异的来源，优先级高于你的默认审美）

- **Token 全部照搬**：把 DESIGN.md 的 YAML Token 逐值转成 CSS 自定义属性
  （`--primary`、`--radius-card`、`--shadow-card`、`--space-scale`…），页面样式
  **只引用这些变量**，禁止硬编码任何颜色/圆角/阴影/字体。
- **components 指引**：规范中的 `components.*`（如 button-primary 的
  padding/rounded/色引用）决定对应组件的真实样式。
- **指标决定气质**：规范散文里的 Density/Variance/Motion 指标必须落地——
  - Density 高 → 紧凑留白，低 → 慷慨呼吸；
  - Variance 高 → 版式允许不对称、错位、超大标题；低 → 严格网格；
  - Motion 高 → 过渡时长足、有入场动效；为 0 → 禁用一切 transition/animation。
- **Do's and Don'ts 是红线**：逐条遵守，与需求冲突时以规范为准并在信息条注明。
- 无指标的规范按你对其 Overview 文气的理解执行，宁可接近规范原文也不要折中。

## 三、功能需求（对所有规范一致）

左侧导航 + 七个视图（视图间切换无需刷新）：

1. **概览**：4 张 KPI 卡（大数字、环比涨跌、迷你趋势线）、团队动态时间线、
   收入构成条形列表。
2. **数据表格**：≥24 行订单：搜索、状态筛选（已支付/处理中/待支付/已退款
   四语义徽章）、按金额/席位/时间排序、行复选与批量操作条、分页。
3. **组件画廊**：主要/次要/强调/危险/幽灵按钮（各含禁用态）、四语义徽章、
   开关、复选（含半选）、单选组、Tabs、进度条、Alert、Tooltip、骨架屏、
   面包屑、模态框（含打开/关闭交互）。
4. **表单流程**：分组长表单（基本信息/订阅方案选择/权限复选组/通知单选组/
   滑块数值/实时密码一致性校验/计数器 textarea/拖拽上传区）、粘性操作栏、危险区。
5. **分析图表**：时间范围切换的柱状趋势、流量来源环图、转化漏斗、
   7×12 活跃热力图、Top5 产品条形表。全部用规范色 Token 绘制，不引图库。
6. **内容页面**：排版样张（标题阶、引用、行内代码、中英混排、等宽数字）、
   定价三档（含推荐档）、博客卡片。
7. **登录/注册**：双 Tab 认证卡（含校验焦点态、第三方登录按钮）。

### 通用要求

- 键盘可达（Tab 顺序、焦点可见），状态色彩对比度遵循规范自身的 Elevation/
  Colors 原则。
- 空状态：任一路径可触达的空列表示例。
- 响应式：≥1024px 完整侧栏；窄屏折叠为顶部标签。

完成后自查：逐条核对第二节，把「哪些界面决策来自规范的哪一行」写进代码顶部注释。
